# 专利/标准说明书文本提取工具

将**发明专利说明书**和**国家标准/行业标准/地方标准**等 PDF 文档在线转换为高质量 JSONL 格式数据，用于本地大模型预训练。

支持单个 PDF 上传、ZIP 批量上传，内置 OCR 与多阶段智能清洗，Docker 一键部署。

---

## 功能

### 专利模式

- 📄 **上传单个 PDF** → 即时 OCR 提取 → 下载 JSONL
- 📦 **上传 ZIP 压缩包**（内含多个 PDF）→ 后台批量并行处理 → 下载合并的 JSONL
- 🧹 **智能清洗**：自动去除专利页脚（CN号、页码、说明书章节名）、扉页元数据（申请号/日、申请人、发明人等）、代理人信息、通用法律套话
- 📐 **语义分段**：按专利章节拆分 + 招投标相关度过滤 + 120~2000字段长控制
- ⚡ **自适应并行加速**：自动检测 CPU 核数、内存、GPU，动态分配最优并行 Worker 数

### 标准模式

- 📄 **上传单个 PDF** → 即时提取 → 下载 JSONL
- 📦 **上传 ZIP 压缩包**（内含多个标准 PDF）→ 后台并行处理 → 下载合并 JSONL
- 🏗️ **章节感知解析**：自动识别标准文档结构（范围、术语、技术要求、附录等）
- 🏷️ **智能分类**：基于章节标题和编号推断 10+ 种预定义类别
- 🧹 **10 阶段清洗流水线**：页眉页脚/封面/目录/公司人名/套话/去重全覆盖
- 📏 **智能分段**：按条款编号（6.1.1）分割 + 长短片合并控制
- 🐳 **Docker 一键部署**

## 快速开始

### 方式一：直接运行（本地开发）

```bash
# 安装依赖
pip install -r requirements.txt

# 启动服务
uvicorn app.main:app --reload --port 8686

# 打开浏览器
open http://localhost:8686
```

浏览器打开 `http://localhost:8686`，选择「专利」或「标准」模式。

### 方式二：Docker 部署

```bash
# 构建并启动
docker compose up -d

# 查看日志
docker compose logs -f

# 停止
docker compose down
```

### 方式三：在远程服务器运行，NAS 上显示页面

程序运行在远程服务器 `59.79.241.152` 上，通过 SSH 端口转发将服务映射到 NAS 本地访问。

**第一步：NAS 上启动远程服务**

在 NAS 的终端（或 SSH 客户端）中执行：

```bash
ssh root@59.79.241.152
cd /root/zhuanli_ext_pretrain-main
source venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8686
```

**第二步：NAS 上建立端口转发**

在 NAS 上新建一个终端窗口（保持上面不关）：

```bash
ssh -L 8686:localhost:8686 root@59.79.241.152
```

**第三步：NAS 浏览器访问**

打开 NAS 上的浏览器，访问 `http://localhost:8686`。

**端口被占用**（address already in use）：

```bash
kill -9 $(lsof -t -i :8686)
uvicorn app.main:app --host 0.0.0.0 --port 8686
```

## 使用说明

1. 打开浏览器访问 `http://localhost:8686`（端口转发后）
2. 拖拽或点击选择 PDF / ZIP 文件
3. 选择「专利」或「标准」模式
4. 点击「开始提取」
5. 等待处理完成，下载 JSONL 文件
6. 文件会保存一份在 `outputs/` 目录下

## 自适应并行加速（专利模式）

系统启动时自动检测宿主机器资源，选择最优并行策略：

| 环境 | CPU | 内存 | GPU | 并行 Worker | 策略 |
|------|-----|------|-----|-------------|------|
| 低配机器 | ≤2 核 | ≤4 GB | 无 | 1 | 串行处理 |
| 中配服务器 | 8 核 | 16 GB | 无 | 4~6 | 多进程并行 |
| 高配服务器 | 16+ 核 | 48+ GB | 无 | 8 | 多进程并行 |
| GPU 服务器 | 任意 | 任意 | NVIDIA CUDA | 1~2 | GPU 批量推理 |

- **CPU 模式**：通过 `ProcessPoolExecutor` 启动多个 Worker 进程，每个进程拥有独立的 PaddleOCR 实例，并行处理不同 PDF
- **GPU 模式**：检测到 CUDA 时自动启用 GPU 推理，每次 `predict()` 批量处理多页图像
- **单 PDF 请求**：OCR 在后台进程执行，不阻塞 FastAPI 事件循环

## 数据清洗说明

### 专利模式

提取的文本经过多阶段清洗，确保预训练数据质量：

1. **OCR 行合并**：修复 `\n` 导致的中文句子截断
2. **编号附着**：`[0055]\n内容` → `[0055] 内容`
3. **页脚移除**：去除 `CN 102955986 A + 机明节 + 1/3页` 等专利页脚噪声
4. **扉页元数据移除**：申请公布号/日、申请号/日、申请人、发明人、代理人、专利权人、Int.Cl. 分类号等
5. **公司/人名行移除**：`中油物采信息技术有限公司`、`孙玉华 郭建光` 等
6. **通用套话过滤**：`以上所述仅为本发明的较佳实施例` 等专利法律套话
7. **短片段丢弃**：低于 120 字符的无效样本直接丢弃
8. **招投标相关度过滤**：不含招投标关键词的片段自动过滤

### 标准模式

文本经过 10 阶段清洗处理：

| 阶段 | 处理 | 说明 |
|------|------|------|
| 1 | 文本提取 | PyMuPDF 直接提取（无需 OCR） |
| 2 | 行级清洗 | 去除封面页/标准编号页眉/页码/孤立数字/表格噪声 |
| 3 | 页眉页脚块移除 | 连续 2+ 行的标准页眉块整体删除 |
| 4 | 编号附着 | "6.1.1\n内容" → "6.1.1 内容" |
| 5-6 | 段落去重 | 相邻相似段落自动去重 |
| 7 | 行断裂合并 | 重建被 PDF 截断的句子 |
| 8 | 章节分割 | 按标准文档结构解析章节 |
| 9 | 条款分段 | 按条款号（6.1.1）分割，短片段合并，超长片段拆分 |
| 10 | 质量过滤 | 最小长度 50 字符、噪声比 <0.3、套话过滤 |

#### 去除的噪声类型

- **封面噪声**：中华人民共和国、国家标准、发布日期、实施日期、代替信息
- **页眉页脚**：DB5101/T 214—2025、GB/T 12345—202X、ICS 编码、页码
- **目录行**：带省略号和页码的目录行
- **公司人名行**：封面处的公司/机构名称和署名
- **水印**：征求意见稿、报批稿、试行等
- **套话**：本文件按照 GB/T 1.1 给出的规则起草、起草单位等
- **孤立噪声**：单字符、标点行、表格残留线、序号碎片

## 技术栈

- **后端**: Python FastAPI
- **OCR**: PaddleOCR v3.7+（PP-OCRv6，中文，专利模式）
- **PDF 处理**: PyMuPDF (fitz) — 直接文本提取（标准模式）
- **并行**: `concurrent.futures.ProcessPoolExecutor`
- **资源检测**: psutil + sysctl + /proc/meminfo（专利模式）
- **部署**: Docker + docker-compose
